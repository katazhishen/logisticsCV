
**这张图要表达的核心是**：读码不是终点，是**第①层的一个传感器**。
它的输出必须在第②层变成"动作序列"，在第⑤层的时间预算里跑得下去。

这五层里，**任何一层断掉，整机都是 0 分**：

| 你很强的地方 | 但断在别处 → 结果 |
|-------------|-----------------|
| 读码 100% 准 | 解析错了一组数字 → 搬错颜色 → 0 分 |
| 解析完美 | 读码最坏 540ms 卡住主循环 → 撞障碍物 → 犯规 |
| 什么都对 | 显示装置字太小（<12mm）→ 裁判看不清 → 判违规 |
| 什么都对 | 第二批往暂存区地上一放 → 违反码垛规则 → 0 分 |

> **这就是"联动"的意义**：单项 100 分 ≠ 总分 100 分。
> 你要做的是**找出最弱的那一项**，而不是把最强的那项再练 10%。

## 3. 把读码插进比赛时间轴

规则里的时间线是这样的（初赛）：

```
赛前调试 ──────────┐
                  ├─ 剩 1 分钟：抽签决定任务码（156+123+516+231 这种）
                  ├─ 剩 30 秒：停止运行，待机发车
                  ├─ 一键启动（只按一次，没有第二次机会）
                  └─ 自主完成 → 记成绩；每队两次运行，取最好
```

**读码在这条线上出现几次？答案：至少两次，可能要多次。**

| 时刻 | 读什么 | 为什么 | 读不到怎么办 |
|------|-------|--------|-------------|
| 启动后出发，接近场地内侧 | **A4 码板上的任务码**（80×80mm） | 这是**唯一**的任务来源，抽签时你只知道码板"在某个随机位置"，不知道内容 | 停车 → 后退/前进 2cm 重读（第 09 课：1px≈1mm）→ 最多重试 3 次 |
| 抓取前（对着物料） | **物料颜色**（不是读码，是颜色识别） | 第一组/第三组数字编码的是颜色 | 靠补光/多帧投票 |
| 放置前（对着粗加工区） | **区域编号**（可能是图形/数字/颜色标识） | 第二组/第四组编码的是"放哪个位置" | 依赖定位精度，不依赖视觉 |
| 全程 | 任务码**回显在显示装置上** | 规则要求上部亮光显示、不被遮挡、字高 ≥12mm | 不涉及"读取"，涉及"验收" |

> **⚠️ 一个非常容易忽略的规则细节**：任务码的**第二组和第四组含义不同**。
>
> - 第二组（`123`）= 第一批物料在**粗加工区和暂存区**的放置位置
> - 第四组（`231`）= 第二批物料在**粗加工区**的放置位置
>
> **为什么第四组没有"暂存区"？** 因为规则规定：第二批在暂存区
> **只能码垛在前一批物料之上，且颜色必须一致**。
> 也就是说——**暂存区的位置根本不需要编码，它是被前一批"钉死"的**。
>
> 这是一个典型例子：**读懂了规则，就少写一半代码**。
> 如果你没意识到这点，你会去解析一个"不存在的位置编号"，然后在赛场上发现它和实际对不上。

## 4. 读码模块的"交付契约"

第 10 课的 `RobustReader.read()` 返回 `(text, level)`。这不够。
**上层（决策层）需要的是"可以直接用的结构化任务"**，所以第 08 课的解析器必须接在后面。

完整的交付链是这样的：

```
RobustReader.read(frame)
        ↓  (text="156+123+516+231", level="L0 原图")
parse_task.parse(text)
        ↓  TaskCode(colors_first=(1,5,6), pos_first=(1,2,3),
                    colors_second=(5,1,6), pos_second=(2,3,1))
to_actions(task)
        ↓  [抓取(红)→放置(粗加工1), 抓取(黑)→放置(粗加工2), ...]
主循环执行
```

**这条链上每一步都可能失败，且失败的处理方式完全不同**：

| 失败点 | 现象 | 正确处理 |
|-------|------|---------|
| 读码失败 | `text is None` | **重试**（换位置/换帧），这是"没看见" |
| 解析失败 | `TaskCodeError` | **换一帧重读**，这是"看错了" |
| 语义可疑 | 颜色重复、位置重复 | **不采信，重读**，这是"看了但可能是假的" |
| 动作不可行 | 第二批要放的位置被占了 | **改策略**，这是"看对了但做不到" |

> **这四种失败绝不能都写成一个 `except: pass`。**
> 第一种要等（时间换信息），第二种要重读（信息错了），
> 第三种要交叉验证（信息可能被污染），第四种要改计划（信息是对的，世界不允许）。
>
> **把"失败"按原因分类，是工程能力最核心的一条。**

## 5. 联动点逐个过：读码和其他模块怎么打架

### 5.1 读码 × 定位

码板位置是**随机**的，但码板本身是**已知尺寸**（A4 板，中间 80×80mm 的码）。

于是你可以用第 12 课 A 节的公式反推距离：

```
d = f × W / w        f = 焦距（像素），W = 码的真实宽度 80mm，w = 画面里的码宽（像素）
```

实测（f=1475px）：

| 画面里码宽 | 实际距离 |
|----------:|--------:|
| 200 px | 590 mm |
| 160 px | 738 mm |
| 120 px | 983 mm |
| **80 px** | **1475 mm**（第 09 课的 100% 临界点） |
| 60 px | 1967 mm |
| 40 px | 2950 mm（远超场地尺寸，说明不用短焦镜头时你根本读不到对面墙） |

**两个直接可用的结论**：

1. **场地 2400×2400mm，对角线约 3394mm。** 在最远对角处（d=3400mm），码宽只有
   `w = f×W/d = 1475×80/3400 ≈ 34.7px`，也就是 34.7/29 ≈ **1.2px/格** ——
   第 09 课实测 1.38px/格 就已经读不出，**所以"站在对面墙边读"是不可能读到的**。
   要读 80px 需要 `f = w×d/W = 80×3400/80 = 3400px`，是现在 f 的 2.3 倍
   （要么换长焦、要么提高分辨率，两条路都影响视野）。
   **所以策略必须是"走过去读"，不是"遥遥相望读"。**
2. **读到了码，就顺便量到了距离** —— 同一个 `polygon` 数据算了两次，
   视觉测距**不需要额外的超声波/激光**（但可以有，用来交叉验证）。

### 5.2 读码 × 避障（最凶险的一处）

第 10 课实测：**没码的画面，最坏 540ms/帧**。
而避障需要的是 **高帧率**（越障越早发现越好，10fps 以下基本只能靠碰）。

**冲突是这样发生的**：

```
主循环（单线程，很常见的新手写法）：
  frame = 抓帧()
  text = reader.read(frame)      # ← 最坏 540ms
  avoid(frame)                   # ← 这 540ms 里车还在以 0.3m/s 前进 = 前进 16cm
```

16cm 意味着：**φ50mm 的障碍物，你从"看见"到"撞上"只有 16cm 的余地。**

**三种解法（按推荐顺序）**：

| 方案 | 做法 | 代价 |
|------|------|------|
| **① 设预算**（最简单） | `RobustReader(budget_ms=40)` | 最坏 40ms → 前进 1.2cm，安全 |
| **② 分频扫描** | 每 3 帧才跑一次全流程，其余帧只跑 L0 | 最坏 40ms，平均 14ms |
| **③ 双线程/双进程** | 读码一个线程，避障一个线程 | 复杂度↑，要处理共享帧 |

> **新手最爱的方案是③**（"多线程不就完了"），但它是**最容易翻车的**：
> cv2 的 `VideoCapture` 在多线程里读同一路摄像头会出现帧错乱/双缓冲问题，
> 而且 Python 有 GIL，所谓"并行"其实还是抢同一颗核。
>
> **先试①，一分钟就能验证；不够再上②；③是最后手段。**

### 5.3 读码 × 抓取

第一组/第三组数字编码的是**颜色 + 搬运顺序**（红1 黄2 蓝3 绿4 黑5 浅蓝6）。

于是"任务码"到"动作"的映射是：

```
第一组 156  →  第 1 个搬红色(1)、第 2 个搬黑色(5)、第 3 个搬浅蓝(6)
第二组 123  →  这三个分别放在 粗加工1 / 粗加工2 / 粗加工3（按顺序对应）
```

**这里有三个必须注意的坑**：

1. **顺序是"组的位序"，不是"数字大小"**。`156` 是"红→黑→浅蓝"，
   不是"先搬 1 号颜色、再搬 5 号颜色"这么抽象——它就是**你抓取的先后**。
2. **颜色识别可能错**（浅蓝 6 和蓝色 3 在白光下很像）。第 08 课 md 里说过：
   浅蓝是 PLA、蓝是 ABS，**材质不同 → 反光特性不同**，可以用多帧取平均 + 色相直方图区分。
3. **第二批在暂存区必须码垛且颜色一致**（规则）→ 这意味着你在第一批放置时
   **就要为第二批留出"同色叠放"的空间**。这是**规划问题**，不是视觉问题。

### 5.4 读码 × 显示装置（合规性）

规则原文要求：任务码显示装置必须在**上部醒目位置、亮光显示、不被遮挡、字体高度不小于 12mm**。

第 08 课我们算过：**150 DPI 下 12mm ≈ 71 像素**。

```
12 mm ÷ 25.4 × 150 = 70.9 px   → 至少 71 px 高的字
```

**你的第一版示例用了 64px（≈10.8mm），不合格。** 这就是"细节扣分"的典型：
技术上完全正确，但**规格不达标**。

> **验收方法（别靠目测）**：在代码里直接算
> ```python
> px = round(12 / 25.4 * DPI)     # DPI 是你渲染面板用的分辨率
> assert font_size >= px, f"字高 {font_size}px < {px}px（12mm 不合格）"
> ```
> **把规则写成断言**，比背规则可靠得多。

### 5.5 读码 × 无线通信（为什么这条要单独讲）

规则明确：**不允许遥控**。

但规则同时要求机器人"具备无线通信功能"。这不矛盾：

| 允许 | 不允许 |
|------|--------|
| 赛前调试时无线传日志/改参数 | 比赛中通过无线**发送控制指令** |
| 运行中无线回传状态（供记录） | 用无线**代替自主决策** |
| 无线下载调试固件 | 人工遥控干预运行 |

> **工程上怎么保证不违规**：把无线模块的代码路径**与控制路径物理隔离**——
> 无线只读不写（只发不收），或者干脆运行期断开接收。
> **"我保证不按"不如"代码里没有这条路径"**，后者才是可审计的。

### 练习 11-A　写主流程伪代码

把"出发 → 找到码板 → 读码 → 解析 → 搬 6 个物料"写成伪代码。要求标出**每个失败点的降级路径**。

<details>
<summary>参考思路</summary>

```python
def run_match():                                  # 整场主流程：任何一步失败都要走完
    task = None                                   # 任务码先留空，读到才填

    # ═══ 1. 找码板：位置随机，沿路线扫一圈 ═══
    for waypoint in scan_route():                 # 第 11 课：读码要"走过去读"
        goto(waypoint)                            # 开到扫描点停稳再拍，别边开边读
        task = try_read_task(max_frames=30)       # 内部：reader + parse + 语义校验
        if task:                                  # 读到且解析合法就不用再扫了
            break                                 # 提前退出循环，省下时间
    if task is None:                              # 扫完一圈仍然没读到
        return fallback_no_task()                 # 降级：按最常见任务码赌一把（能得部分分）

    # ═══ 2. 第一批：组内位序就是抓取顺序 ═══
    for color, pos in zip(task.colors_first, task.pos_first):
        if not goto_color(color):                 # 颜色找不到
            continue                              # 跳过这个，别毁掉全局
        grab()                                    # 对准了才夹，夹稳了才移动
        put_coarse(pos)                           # 粗加工区
    # 同样三件再走一遍：这次送进暂存区
    for color, pos in zip(task.colors_first, task.pos_first):
        put_buffer(color)                         # 暂存区：位置由规则钉死，不需编号

    # ═══ 3. 第二批：暂存区只能叠在同色之上 ═══
    for color, pos in zip(task.colors_second, task.pos_second):
        grab()                                    # 抓的是第二批的物料
        put_buffer_stack(color)                   # 叠放：如果下面没有同色 → 换策略
        put_coarse(pos)                           # 第四组给的是粗加工区位置
```

**关键设计点**（对照检查你有没有想到）：

1. **扫描路线要覆盖码板可能出现的整个区域**，而不是"开出去看一眼"
2. **`fallback_no_task()` 不是"放弃"**，是"用统计上最常见的任务码赌一把"——
   因为两次运行取最好成绩，赌对了就是分，赌错了也不比 0 分更糟
3. **单个物料失败不要中断整场**（`continue`），因为每个物料都有独立分数
4. **暂存区不需要位置编号**（第 3 节讲的规则细节）

### 练习 11-B　算一笔时间账

已知：摄像头 20fps（50ms/帧）、读码预算 40ms、单程走到码板 8 秒、
每个物料抓取+放置 12 秒。问：**搬完 6 个物料总共至少多久？两次运行够不够？**

<details>
<summary>参考思路</summary>

```
找码板：8s（走过去）+ 0.04s × 最多 30 帧 = 8s + 1.2s ≈ 9.2s
搬 6 个：6 × 12s = 72s
第一批去暂存区：+8s
第二批回粗加工区：+8s
合计 ≈ 97s ≈ 1 分 37 秒
```

**结论**：**时间不是瓶颈，稳定性才是。**
规则里"两次运行取最好成绩"意味着你有一次**可以失败**的机会 —— 所以
**第一次运行应该打得稳（宁可慢），不要打得激进**。

> **反过来算**：如果你为了快把抓取时间压到 6 秒，整场省了 36 秒，
> 但失误率从 10% 涨到 40% —— 这笔交易**明显亏**。
> 因为**分数的量级是"每个物料 1~15 分"，不是"每秒 X 分"**。

</details>

### 练习 11-C　找出你系统里最弱的一环

把你现在（或计划中）的系统列成 5 行，每行给一个"信心分"（1~5），找出最低的那行。

<details>
<summary>参考思路（示例）</summary>

| 环节 | 信心 | 依据 | 风险 |
|------|-----:|------|------|
| 读任务码 | 5 | 第 09 课压测 80px 全 100% | 低 |
| 解析任务码 | 5 | 11 个非法用例全覆盖 | 低 |
| **颜色识别** | **2** | 浅蓝/蓝没实测过 | **高 → 优先补** |
| 圆环放置精度 | 3 | 没测过重复定位误差 | 中 |
| 时间预算 | 3 | 没在真实负载下测过 | 中 |

**然后做一件事：只补最低那行。** 把颜色识别补到 4 分，总分立刻上一个台阶；
把读码从 5 分补到 5.5 分，总分**纹丝不动**。

> **这是"联动复习"最实际的产出**：不是让你什么都会，而是让你**知道该练哪一项**。

</details>

## 8. 自测题（跨课综合）

**1. 任务码是 `246+312+135+213`。请说出第一批三个物料搬什么颜色、按什么顺序。**

<details><summary>答案</summary>
第一组 `246` → 第 1 个搬黄色(2)、第 2 个搬绿色(4)、第 3 个搬浅蓝(6)。
第二组 `312` → 分别放在粗加工区位置 3、1、2（**与颜色一一对应、按位序**）。
注意不是"按数字大小排序"，是"第 i 位颜色对应第 i 位位置"。
</details>

**2. 为什么第四组数字不需要编码"暂存区位置"？**

<details><summary>答案</summary>
因为规则规定第二批在暂存区**只能码垛在前一批物料之上，且颜色必须一致**。
位置由第一批的放置结果唯一确定，没有选择余地，所以不需要编码。
**读懂规则能省一半代码**，这是本课最重要的一句话。
</details>

**3. 你的读码器读到 `156+123+516+231`，但颜色识别模块报告"第 2 个物料是蓝色(3)"。谁错了？怎么处理？**

<details><summary>答案</summary>
**不能直接判定谁错**，因为两种可能都真实存在：
① 颜色识别错了（浅蓝 6 被误判成蓝 3，白光下很常见）；
② 读码读串了（zbar 极少错，但反光/屏摄可能）。
正确处理：**交叉验证** —— 任务码里的颜色集合是 `{1,5,6}`，如果颜色模块报 3，
说明**至少有一个环节错了**。此时应该多帧重读任务码（3 帧一致才算）、
同时用多角度/多光源重测颜色。**两边都是"证据"，不能预设哪边对。**
</details>

**4. 车以 0.3 m/s 行驶，读码最坏一帧 540ms。障碍物直径 50mm。从"看见"到"撞上"还剩多少距离？够不够？**

<details><summary>答案</summary>
0.3 m/s × 0.54 s = **0.162 m = 162mm**。
障碍物直径 50mm，所以"看见时车头距障碍物多远"才是关键 ——
但**摄像头装在车头上，看见时距离≈0**，所以实际是"这 540ms 里往前冲 162mm"，
**必然撞上**。结论：**必须设预算**（40ms → 12mm，勉强安全），或降低行驶速度。
</details>

**5. 第 10 课的 `--survey` 里 27/33 张在 L0 就成功。如果有个队友说"那我们只要 L0 就够了"，你同意吗？**

<details><summary>答案</summary>
**不同意，但可以验证**。第 10 课练习 10-D 实测：删掉 L0 后 29 张仍然全部成功
（改由 L1 中值/ L2 OTSU 接手）—— 这**恰好说明**"单个级别不是不可替代的"。
但 L1~L8 的价值不在"平时能读到"，而在"**极端情况下能读到**"：
`03_size_30.png` 只有 L7 放大4x 能读，`06_noise.png` 只有 L1 中值能读。
**平时用不上的级别，是你的保险。** 保险平时也用不上，但没人因此不买。
</details>

**6. 为什么"两次运行取最好成绩"这条规则，反而要求你第一次跑得保守？**

<details><summary>答案</summary>
因为**期望值**：激进策略单次期望可能是 60 分但方差大（可能 0）；
保守策略单次 45 分方差小。两次取最好成绩时，
"保守+保守"的期望≈48，"激进+激进"的期望可能只有 40（因为两次都可能崩）。
**当你有多次机会且取最好，风险厌恶反而提高期望收益。** 这是博弈论里的基本结论。
</details>

## 9. 小结

| 你学到的 | 一句话 |
|---------|--------|
| 读码的定位 | 它是第①层的一个传感器，不是终点 |
| 联动风险 | 单项 100 分 ≠ 总分 100 分，先找最弱一环 |
| 规则细节 | 第四组不编码暂存区（因为规则钉死了）；读懂规则省一半代码 |
| 交付契约 | 读码 → 解析 → 动作，四类失败四种处理，不能都写 `except: pass` |
| 读码×定位 | 同一个 polygon 顺便算出距离（d = fW/w），不需要额外传感器 |
| 读码×避障 | 540ms 卡主循环 = 前进 16cm = 必撞；预算 40ms 降到 1.2cm |
| 读码×抓取 | 组内位序 = 抓取顺序；浅蓝/蓝要靠材质与多帧区分 |
| 读码×显示 | 12mm → 150DPI 下 71px，把规则写成 `assert` |
| 读码×无线 | 无线只读不写，代码里**没有**接收控制指令的路径 |
| 状态持久化 | 任务码落盘，重启后先读它（一键启动只按一次） |
