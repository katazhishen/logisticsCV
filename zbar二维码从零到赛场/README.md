# 用 zbar 读二维码：从零到赛场

> 写给大一算法组新生的第一份视觉教程。
> 目标只有一个：**让机器人看一眼二维码，就知道这一局该干什么。**

---

## 一、先回答三个问题

**1. 为什么算法组要学读二维码？**

翻开《智能赛道命题.pdf》，智能搬运赛项的功能要求里有一句：

> 能读取二维码、条码、图形、数字、文字、颜色等信息 —— 完全自主

任务码（比如 `156+123+516+231`）就是这一局比赛的**全部指令**：
搬哪三个颜色、按什么顺序、放到几号圆环、第二批怎么码垛，全在这 15 个字符里。

读不出来 = 不知道干什么 = 0 分。这是整场比赛的**第一个门槛**，也是最早能跑通、
最能给你正反馈的一环。所以算法组从它开始练手，是最划算的。

**2. zbar 是什么？**

`zbar` 是一个专门"找码 + 认码"的 C 语言库，2006 年就有了，Linux/树莓派/树莓派
摄像头生态里到处是它。`pyzbar` 是它的 Python 包装，让你三行代码就能读码。

它和 `OpenCV` 的 `QRCodeDetector` 是**两套独立实现**：一套用 ZBar 自己的扫描线算法，
一套用 OpenCV 的图形检测。它们各有盲区 —— 这一点第 09 课会用数据说清楚，
第 10 课会把两者拼成一个更结实的读码器。

**3. 这份教程和网上那些"3 行代码读二维码"有什么区别？**

网上那 3 行代码只能在**干净图片**上工作。而赛场上的真实画面是：
A4 板歪着贴在场地边缘、80mm 的码在画面里只有几十像素、头顶灯管一片反光、
车还在抖。这份教程花 10 课时间，把"读不出"的每一种原因都拆开、量化、给解药。

**现在就想跑？** 三条命令，三十秒见效（在教程根目录下执行）：

```bash
.venv/bin/python code/env_check.py              # 环境体检，8 项应全 OK
.venv/bin/python code/lesson03_read_one.py      # 批量读全部素材图，最后会给出结论
.venv/bin/python code/lesson10_reader.py --self-test   # 11 级流水线自动挑药
```

这三条能过，说明环境和代码都是好的，可以直接从第 03 课往下学。

**关于 zbar 本体**：正常情况 `sudo apt install libzbar0` 就够了。但这台机器没有 sudo

**如果你以后在别的机器上有 sudo，直接装系统的就行，bootstrap 会自动走"系统"这条路。**

## 五、怎么用每一课

每一课都是同一个结构，别跳着看：

```
1. 本课要解决的问题     ← 先知道"为什么学这个"
2. 打比方讲原理         ← 建立直觉，不要背
3. 动手（命令 + 代码）   ← 一定要自己跑
4. 参考答案 / 参考结果   ← 拿你跑的输出去对
5. 批注                 ← 那些"书上不写但会坑你"的细节
6. 常见错误             ← 报错信息 → 原因 → 解法
7. 自测题               ← 答不上来就回去重看，别糊过去
8. 下一课衔接           ← 一环接一环的原因
```

**所有命令都在教程根目录下执行**（就是这个 `zbar二维码从零到赛场/` 文件夹）：

```bash
cd "/home/kata/Desktop/logisticsCV/zbar二维码从零到赛场"
```

脚本里都用 `os.path.dirname(os.path.abspath(__file__))` 定位自己的位置，
所以理论上你在哪儿跑都行 —— 但为了少踩坑，建议就在根目录跑。

## 七、一句提醒

这份教程里所有"结论"都是用实跑数据得出的，包括几个**反直觉**的：

- 安静区（白边）单独放白底时 `border=0` 也能读（第 04 课实测）
- 放大码**不一定**要用最近邻插值，要看原图是怎么缩小的（第 09 课实测）
- zbar 的耗时和"内容"强相关，不是固定值（第 09 课实测）
- 流水线注释写着"按成本从低到高排序"，实际把最贵的三级排在了第三位（第 10 课自查抓出来的）
- `straight` 摆正的硬要求是"每格 ≥2 像素 + 最近邻"，补白边只是保险（第 12 课实测）

**别背我的数字，学会我的方法。** 你的摄像头、你的场地光照、你的打印纸，
数据一定和这里不一样。每课都留了"换你自己的图再跑一遍"的口子，那才是真正学到的东西。
