## 1. 先读懂赛题：这 15 个字符在说什么

命题原文（智能搬运赛项）：

> 任务码由四组三位数组成，四组数之间用"+"连接。
> 第一组代表**第一批三个物料的颜色与搬运顺序**；
> 第二组代表**第一批物料在粗加工区和暂存区的放置位置**；
> 第三组代表**第二批物料的颜色与搬运顺序**；
> 第四组代表**第二批物料在粗加工区的放置位置**。
> 颜色编号：红 1、黄 2、蓝 3、绿 4、黑 5、浅蓝 6。示例：`156+123+516+231`

拆开看 `156+123+516+231`：

```
    1 5 6        +   1 2 3        +   5 1 6        +   2 3 1
  ┌──┴──┐         ┌──┴──┐          ┌──┴──┐          ┌──┴──┐
  第 1 批的颜色     第 1 批的          第 2 批的颜色     第 2 批的
  和搬运顺序        放置位置           和搬运顺序        放置位置
  ↓                ↓                 ↓                 ↓
  红 → 黑 → 浅蓝    1 号 → 2 号 → 3 号   黑 → 红 → 浅蓝     2 号 → 3 号 → 1 号
```

**四句话就念完了**：

1. 第一批依次搬 **红、黑、浅蓝**，分别放到 **1、2、3 号位**
2. 第二批依次搬 **黑、红、浅蓝**，分别放到 **2、3、1 号位**

> **批注：为什么是"三"？**
> 命题规定第一批、第二批各三个物料（6 种颜色 × 2 个 = 12 个物料，但每批只搬 3 个）。
> 数字 3 不是巧合，它直接决定了"每组必须是 3 位数"。

> **批注：位置编号到底指什么？**
> 原文只说"放置位置"。结合评分规则（1~6 环圆环、越靠里分越高），
> 本教程把"位置"理解为**粗加工区里的第几号圆环/格子**（1、2、3）。
> **但赛场说明可能另有约定** —— 你上场前必须确认这一点。
> **这里给你一个通用教训：赛题文字有歧义时，代码要把"编号 → 物理位置"抽成一张表，
> 而不是写死在逻辑里。** 本课后面会看到这张表在哪。

> **批注：颜色编号为什么这样排？**
> 红1 黄2 蓝3 绿4 黑5 浅蓝6 —— 注意前 4 个是"纯色系"（红黄蓝绿，RGB 色轮顺序），
> 后 2 个是"非彩色系"（黑、浅蓝）。**这不重要，但你必须一字不差地抄对** ——
> 把 5 当黑色、6 当浅蓝，抄反了整场比赛都搬错。

## 3. 关键代码 1：归一化（NFKC）

```python
def normalize(raw: str) -> str:
    s = unicodedata.normalize("NFKC", raw)   # 全角→半角，兼容字符→标准字符
    s = s.replace("\u3000", " ")             # 全角空格
    s = "".join(s.split())                    # 去掉所有空白（含 \n \t 空格）
    return s
```

### `NFKC` 是什么？

Unicode 标准定义了四种"归一化形式"：NFC、NFD、NFKC、NFKD。
其中 **K 表示"兼容"（Kompatibility），C 表示"组合"**。

**NFKC 干的事**：把"看起来差不多但码位不同"的字符，统一成标准形式。

| 你输入的 | NFKC 之后 | Unicode 码位变化 |
|---------|----------|-----------------|
| `１`（全角） | `1` | U+FF11 → U+0031 |
| `＋`（全角） | `+` | U+FF0B → U+002B |
| `Ａ`（全角） | `A` | U+FF21 → U+0041 |
| `①` | `1` | U+2460 → U+0031 |

> **打个比方**：NFKC 就像**把各种方言统一成普通话**。
> `１` 和 `1` 在肉眼看来是一个东西，在计算机里却是两个不同的字符（码位不同）。
> `int("１")` 会直接抛 `ValueError` —— 因为 Python 不认识这个字符是数字。
> **NFKC 就是把所有"方言"翻译成"普通话"。**

> **批注：为什么不用 `str.replace("１", "1")` 一个个换？**
> 因为全角数字有 10 个、全角加号 1 个、还有各种奇奇怪怪的兼容字符（比如 `¹` `½`）。
> **一个个列举永远会漏。NFKC 是标准库给的完整映射表，一行搞定。**
> 这是"用标准库而不是自己造轮子"的典型例子。

### 为什么要 `"".join(s.split())`？

`s.split()` 不带参数时，按**任意空白**（空格、`\n`、`\t`、全角空格）切分并丢弃空串，
`"".join(...)` 再把它们拼回去 —— 等于**删掉所有空白**。

```python
"  156 + 123 + 516 + 231 \n".split()   # → ['156', '+', '123', '+', '516', '+', '231']
"".join(_)                              # → '156+123+516+231'
```

> **为什么敢删掉所有空白？**
> 因为任务码里**空格没有任何语义**（不像英文空格是分隔词）。
> 删掉所有空白是**安全且必要**的。**反过来，如果格式里空格有意义，就绝不能这么删。**

## 4. 关键代码 2：正则表达式

```python
PATTERN = re.compile(r"^[1-6]{3}(?:\+[1-6]{3}){3}$")
```

逐段拆：

| 片段 | 含义 |
|------|------|
| `^` | 从字符串开头 |
| `$` | 到字符串结尾（配合 `fullmatch` 使用更严谨） |
| `[1-6]` | 一个字符，必须是 1~6（正好是 6 种颜色） |
| `{3}` | 重复 3 次 |
| `(?:\+[1-6]{3})` | 一个非捕获组：`+` 后面跟 3 个 1~6 |
| `{3}` | 这一整组再重复 3 次 |

合起来就是：**"3 个数字，然后 (+3 个数字) 重复 3 次"** = 恰好 4 组 × 3 位。

> **为什么用 `[1-6]` 而不是 `\d{3}`？**
> `\d` 允许 0、7、8、9，但颜色编号只有 1~6。
> **用 `[1-6]` 在正则层面就挡掉了非法数字** —— 这样错误信息可以更精确：
> `\d` 会放行 `230`，然后你要在语义层再发现"0 不是颜色"，两层都在干同一件事。
> **能在一层拦住的，不要留到下一层。**

> **批注：`(?:...)` 为什么不写 `(...)`？**
> `(...)` 是**捕获组**，会把它匹配的内容存进 `group(1)`，占用内存也更慢。
> `(?:...)` 是**非捕获组**，只分组不捕获。**你不需要那个值，就别捕获。**

## 5. 动手 2：错误输入能不能说清"错在哪"

### 参考结果（本机实测，逐字）

```
======================================================================
第 2 步：错误输入 —— 能不能说清『错在哪』？
======================================================================
  输入 '156+123+516'              被拦下：应该用 + 分成 4 组，实际分了 3 组：['156', '123', '516']
  输入 '156+123+516+231+222'      被拦下：应该用 + 分成 4 组，实际分了 5 组：['156', '123', '516', '231', '222']
  输入 '156+12+516+231'           被拦下：第 2 组『12』长度是 2，必须是 3 位
  输入 '156+123+516+23X'          被拦下：第 4 组『23X』里有非法字符 ['X']，只能是 1~6
  输入 '156+123+516+230'          被拦下：第 4 组『230』里有非法字符 ['0']，只能是 1~6
  输入 '156+789+516+231'          被拦下：第 2 组『789』里有非法字符 ['7', '8', '9']，只能是 1~6
  输入 '155+123+516+231'          被拦下：第 1 组『155』里有重复颜色 —— 赛题要求三种物料颜色不同
  输入 '156+113+516+231'          被拦下：第 2 组『113』里有重复位置 —— 赛题要求放在 1、2、3 号不同圆环上
  输入 ''                         被拦下：内容为空
  输入 None                       被拦下：内容为空
  输入 'hello'                    被拦下：应该用 + 分成 4 组，实际分了 1 组：['hello']
```

### 这 11 条错误信息，值得逐条品一下

**① 分组数不对**（`156+123+516`）：直接告诉你"实际分了 3 组"，还把分组内容打印出来。
**好处**：你一眼看到是少了一组还是多了一组、少的是哪一组。

**② 某组长度不对**（`156+12+516+231`）：精确到"第 2 组，长度 2"。
注意它**能定位到组**，因为前面分组已经成功了 —— 这叫**分阶段校验**。

**③ 非法字符**（`23X`、`230`、`789`）：把**所有**非法字符都列出来（`['7','8','9']` 而不是只报第一个）。
**好处**：如果码是印错的，你能一次看到全部错处，而不用改一个跑一次。

> **批注：为什么要打印"所有"非法字符？**
> 因为这是给**调试者**看的。你第一次可能只修对 7，8 还错着，又要跑一次。
> **报错要把"所有已知问题"一次说完**，这是编译器/检查器类工具的通用设计原则。
> 实现就是 `sorted(set(ch for ch in group if ch not in "123456"))`。

**④ 语义错误**（`155` 重复颜色、`113` 重复位置）：见下一节。

**⑤ 空内容**（`''`、`None`）：统一报"内容为空"，不报 `AttributeError`。
**好处**：调用方不用先判断 `None`，解析器自己处理。

> **一个设计细节**：`None` 也能被正确拦下，靠的是
> ```python
> if not raw:
>     raise TaskCodeError("内容为空")
> ```
> **`not raw` 一行同时覆盖了 `None`、`""`、`0`、`[]`** —— 这是 Python 的"真值测试"。

## 6. 为什么必须有"语义校验"？（本节是本课的思想核心）

正则只能保证"**形状**对"：4 组 × 3 位 × 每个都是 1~6。
但下面两个字符串**形状完全合法**：

```
155+123+516+231      ← 第 1 组"155"：红色、黑色、黑色
156+113+516+231      ← 第 2 组"113"：1 号、1 号、3 号
```

**为什么它们是错的？** 因为赛题隐含了两个约束：

| 约束 | 来自哪 | 为什么 |
|------|--------|--------|
| 第一批 3 个物料**颜色不同** | 原料区每种颜色有 2 个，但要搬 3 个 | 同一批搬两个同色没有意义（也无法区分先后顺序） |
| 第一批 3 个位置**互不相同** | 评分是"放到不同圆环上" | 两个物料放同一个圆环 → 叠在一起，第二个拿不到分 |

> **这两条赛题原文并没有明说！** 它们是从"3 个物料 + 6 种颜色 × 2 个 + 圆环评分"**推出来的**。
>
> **这就是"读赛题"和"抄赛题"的区别**：
> 抄赛题 = 把规则一条条实现。读赛题 = **把规则之间的隐含约束也挖出来**。
> 后者才是算法组真正的价值。

### 但语义校验挡不住什么？

脚本第 3 步会诚实地告诉你：

```
  语义校验（颜色不重复、位置不重复）能挡掉其中一部分。
  严格来说它挡不住 ①，所以正式比赛还要加『确认机制』：
  读到码 → 显示在屏幕上 → 等 0.5 秒再读一次，两次一致才认。
  这套机制第 10 课会实装。
```

**情况 ①：你读到了别人的码/上一轮的码。**
内容完全合法（甚至可能是"正确"的任务码），但**不是你的任务**。
语义校验毫无办法 —— 因为它检查的是"形状和内部一致性"，不检查"是不是该读这个"。

### 真正的解法：三道防线

| 防线 | 做法 | 挡什么 |
|------|------|--------|
| 第 1 道：形状校验 | 正则 `^[1-6]{3}(\+[1-6]{3}){3}$` | 长度、字符集 |
| 第 2 道：语义校验 | 颜色不重复、位置不重复 | 形状合法但逻辑荒谬的码 |
| 第 3 道：**确认机制** | 连续 N 帧读到同一内容才认 + **显示在屏幕上让人确认** | 读串码、读错码 |

> **第 3 道防线里"显示在屏幕上"这半句，恰好就是命题强制要求的"任务码显示装置"**。
> 命题要求"亮光显示、字体 ≥12mm" —— **不是为了好看，是为了让裁判/你能看清它读到了什么**。
> **赛题的每一条要求背后都有一个失败案例**，这句话在工程比赛里几乎总是成立的。

## 7. 关键代码 3：把解析结果做成对象

```python
@dataclass
class TaskCode:
    raw: str
    colors_first: tuple[int, int, int]     # 第 1 组：第一批颜色，按搬运顺序
    pos_first: tuple[int, int, int]        # 第 2 组：第一批放置位置
    colors_second: tuple[int, int, int]    # 第 3 组
    pos_second: tuple[int, int, int]       # 第 4 组

    def summary(self) -> str:
        a = "、".join(COLOR_NAME[c] for c in self.colors_first)
        b = "、".join(COLOR_NAME[c] for c in self.colors_second)
        return (f"第1批：依次搬 [{a}] → 放到圆环 {list(self.pos_first)}\n"
                f"第2批：依次搬 [{b}] → 放到圆环 {list(self.pos_second)}")
```

> **为什么用 `dataclass` 而不是返回一个 dict？**
>
> | 方式 | 优点 | 缺点 |
> |------|------|------|
> | `dict` | 灵活 | **打错键名不报错**，`t["color_first"]` 是 `None` 而不是异常 |
> | `dataclass` | **字段名写错立刻 AttributeError**，有类型提示，能自动打印 | 稍微啰嗦 |
>
> **在一个人维护、要写几百行的项目里，`dataclass` 的"打错就报错"能省你几个小时。**
> 这是"用类型换安全"的典型取舍。

> **为什么字段类型写 `tuple[int,int,int]` 而不是 `list`？**
> 因为**任务码是只读的**。如果给 `list`，某处代码 `t.pos_first.append(4)` 就把它变成 4 组了，
> 后面的代码全乱。**`tuple` 在类型层面就堵死了这种意外。**
> 这叫 **"不可变优先"（immutable by default）**，是防 bug 的低成本手段。

## 8. 把任务单渲染到"显示装置"上

```
【第 4 步】把任务单渲染成『显示装置』上要显示的样子
  已生成显示装置示意图：.../assets/21_display_panel.png
  尺寸 800x240；按 150DPI 换算，64px 高 ≈ 10.8mm，
  正式作品请把字号调到 ≥12mm 对应的像素数（150DPI 下约 71px 起）。
```

命题原文：

> 该装置必须放置在搬运机器人上部醒目位置，**亮光显示**，且不被任何物体遮挡，
> **字体高度不小于 12mm**

### 12mm 到底是多少像素？—— 一个必须会算的换算

**关键概念：像素和毫米之间没有固定关系，必须知道 DPI（每英寸多少点）。**

```
1 英寸 = 25.4 mm
150 DPI → 1 mm = 150 / 25.4 = 5.906 px
```

所以：

| 要求 | 150 DPI 下 | 计算 |
|------|-----------|------|
| 字体高度 12mm | **≥ 71 px** | 12 × 5.906 = 70.9 |
| 本示例用的 64px | **10.8 mm** ← 不够！ | 64 / 5.906 = 10.8 |

> **⚠️ 这是一个真实存在的坑**：`assets/21_display_panel.png` 用的是 64px 字体，
> 换算下来只有 **10.8mm < 12mm，不合格**。
> **如果这是要拿去打印/贴到车上的图，裁判可以直接判你不符合要求。**
>
> **正确做法**：先确定你的屏幕/LED 面板的**实际像素密度**，再反算需要多少像素：
> ```
> 需要像素 = 12mm × (DPI / 25.4)
> ```
> 如果你用的是 3.5 寸 480×320 的屏（约 165 DPI），12mm ≈ 78px。
> 如果你用的是普通 0.96 寸 OLED（128×64，约 145 DPI），**你要显示 12mm 高的字，
> 屏幕本身才 64 像素高 —— 根本装不下！**
> **这就是"赛题要求"倒逼"硬件选型"的真实例子。**

> **批注：那怎么办？**
> 换大屏（至少屏高 ≥ 需要像素数 × 行数）、或用点阵 LED 模块拼、
> 或只显示任务码一行大字（一行 71px 高，屏高 ≥ 80px 就够）。
> **本教程的立场：显示内容由算法组定，但"算清楚需要多少像素"是算法组必须提供的数据。**

## 9. 动手 3：从一张图到一份任务单（全流程串起来）

```
【第 5 步】和读码串起来 —— 从一张图到一份任务单
  第 1 步 读码 → '156+123+516+231'
  第 2 步 解析 → 合法 ✓
  第 3 步 生成动作序列：
         [第一批 1/3] 去原料区抓 红色(id=1) → 放到 1 号圆环
         [第一批 2/3] 去原料区抓 黑色(id=5) → 放到 2 号圆环
         [第一批 3/3] 去原料区抓 浅蓝(id=6) → 放到 3 号圆环
         [第二批 1/3] 去原料区抓 黑色(id=5) → 码垛放到 2 号圆环
         [第二批 2/3] 去原料区抓 红色(id=1) → 码垛放到 3 号圆环
         [第二批 3/3] 去原料区抓 浅蓝(id=6) → 码垛放到 1 号圆环
  —— 到这里，『读码』这件事才真正对机器人有用。
```

### 注意这 6 行里的三个信息

1. **顺序信息**：第一批是"红 → 黑 → 浅蓝"，不是随便抓。**搬运顺序有分**。
2. **"码垛"这个词**：第二批的目标位置若已有同色物料，就必须**叠在上面**（命题原文：
   "第二批在暂存区只能码垛在前一批物料之上且颜色一致"）。**这是六个动作里唯一的物理约束。**
3. **`id=1`**：颜色编号要**跟着物料走**。你的视觉识别模块认出"红色"之后，
   必须能映射回 `1` 这个编号 —— **两个系统之间的"协议"就是这个数字**。

> **为什么叫"动作序列"而不是"任务单"？**
> "任务单"是给人看的，"动作序列"是给状态机吃的。
> **机器人的主循环应该是一个状态机：`IDLE → GO_TO_SOURCE → GRAB → GO_TO_RING → PLACE → …`**
> 每个状态执行完推进到下一个。**这张 6 行的表就是状态机的输入。**
> 第 11 课（联动复习）会讲这个状态机怎么和"定位/避障/视觉"配合。

### 参考答案

**8-A**

| 输入 | 结果 |
|------|------|
| `246+312+135+213` | **合法**。第1批：黄→绿→浅蓝，放到 3、1、2 号；第2批：红→蓝→黑，放到 2、1、3 号 |
| `555+111+666+222` | **非法**！第 1 组 `555` 三个都是黑色（重复颜色），第 3 组 `666` 三个都是浅蓝。形状合法但语义非法 |
| `123+456+789+123` | **非法**！第 4 组 `789` 含 7、8、9，超出颜色编号 1~6（第 2 组 `456` 合法，是绿、黑、浅蓝） |

> **注意第三个例子**：`123+456+789+123` 里 **`456` 是完全合法的**。
> 这提醒你：**报错要精确到组**，否则你会以为整串都不能用。

**8-B**

```python
def check_stack(tc: TaskCode) -> list[str]:
    """检查第一批与第二批之间『同位置颜色不一致』的冲突。"""
    problems = []
    first = dict(zip(tc.pos_first, tc.colors_first))     # 位置 → 颜色
    for pos, color in zip(tc.pos_second, tc.colors_second):
        if pos in first and first[pos] != color:
            problems.append(
                f"{pos} 号位置：第一批是『{COLOR_NAME[first[pos]]}』，"
                f"第二批是『{COLOR_NAME[color]}』—— 码垛要求颜色一致"
            )
    return problems
```

用 `156+123+516+231` 检验：

```
输入 156+123+516+231
  第1批 位置→颜色：{1: 红色, 2: 黑色, 3: 浅蓝}
  第2批 位置→颜色：{2: 黑色, 3: 红色, 1: 浅蓝}
  冲突：
    3 号位置：第一批是『浅蓝』，第二批是『红色』—— 码垛要求颜色一致
    1 号位置：第一批是『红色』，第二批是『浅蓝』—— 码垛要求颜色一致

  （2 号位置两批都是黑色，不冲突 —— 函数只报冲突项，所以 2 号位置不出现在结果里）
```

**结论：`156+123+516+231` 在"暂存区码垛"这条规则下会报 2 个冲突。**

> **⚠️ 但请先别急着判它非法！** 命题说的"码垛颜色一致"是**暂存区**的规则，
> 而第二组/第四组里既有"粗加工区位置"也有"暂存区位置"，**两组位置用的不是同一套编号**。
> 这段代码暴露的是：**"位置编号"这个数据在本教程里是"不分区的 1~3"，
> 而赛题实际要求分区域解释。**
>
> **这是一次真实的"模型不够用"的发现。**
> 工程上的处理办法不是"把规则硬塞进现在的模型"，而是：
> 1. 承认模型不足（`TaskCode` 需要"位置 → 区域"的映射）
> 2. **先记下来，去确认赛场说明**
> 3. 确认后把 `TaskCode` 扩成 `Pos = namedtuple("Pos", "zone index")`
>
> **能发现"我的模型不够"，比写出能跑的代码更重要。** 这就是我把这个练习放上来的原因。

**8-C**

```python
def locate(raw: str, group_idx: int, ch_idx_in_group: int) -> int:
    """把『第几组第几个字符』换算成『原始字符串的第几个字符』。"""
    parts = raw.split("+")
    return sum(len(p) for p in parts[:group_idx]) + group_idx + ch_idx_in_group
```

用 `156+123+516+230`（第 4 组第 3 个字符 `0`）验证：

```python
locate("156+123+516+230", 3, 2)   # → 14
```

参考结果：

```
原始串：156+123+516+230
                ↑ 第 14 个字符（0 起算）是 '0'
报错：第 4 组『230』的第 3 个字符（整串第 14 个）『0』非法，只能是 1~6
```

> **`group_idx +` 那一下是"加号的个数"**：第 0 组前面没有加号，第 1 组前面有 1 个……
> **这种"下标偏移"是字符串处理里最容易错的地方，一定要写个测试用例验算。**

**8-D**

```
128 DPI → 1mm = 128 / 25.4 = 5.039 px
12mm 高的字 = 12 × 5.039 = 60.5 px → 至少 61 px
```

屏幕高 **128 px**，字高 **61 px**：

- **能显示 2 行**（61×2 = 122 ≤ 128），**装不下 3 行**
- 所以：任务码一行（61px）+ 状态一行（61px），**正好够，但要留行距就只剩 1 行大字**
- **结论：1.8 寸 160×128 能做"显示装置"，但只够显示 2 行，必须精简内容**

> **这就是"用赛题约束倒推设计"的全过程**：
> 12mm → 61px → 屏高 128 → 最多 2 行 → **所以显示内容只能有 2 行**。
> **先算清楚，再决定显示什么；不是先设计界面，再祈祷它够大。**

**8-E**

```python
def to_actions(self) -> list[dict]:
    acts = []
    for i, (c, p) in enumerate(zip(self.colors_first, self.pos_first), 1):
        acts.append({"batch": 1, "step": i, "color": c,
                     "color_name": COLOR_NAME[c], "target": p, "stack": False})
    for i, (c, p) in enumerate(zip(self.colors_second, self.pos_second), 1):
        acts.append({"batch": 2, "step": i, "color": c,
                     "color_name": COLOR_NAME[c], "target": p, "stack": True})
    return acts
```

参考结果（`156+123+516+231`）：

```python
[{'batch': 1, 'step': 1, 'color': 1, 'color_name': '红色',   'target': 1, 'stack': False},
 {'batch': 1, 'step': 2, 'color': 5, 'color_name': '黑色',   'target': 2, 'stack': False},
 {'batch': 1, 'step': 3, 'color': 6, 'color_name': '浅蓝',   'target': 3, 'stack': False},
 {'batch': 2, 'step': 1, 'color': 5, 'color_name': '黑色',   'target': 2, 'stack': True},
 {'batch': 2, 'step': 2, 'color': 1, 'color_name': '红色',   'target': 3, 'stack': True},
 {'batch': 2, 'step': 3, 'color': 6, 'color_name': '浅蓝',   'target': 1, 'stack': True}]
```

> **注意 `zip` 的用法**：`zip(colors, positions)` 把"颜色序列"和"位置序列"配成对，
> `enumerate(..., 1)` 给出第几个。**两个可迭代对象长度不同时 `zip` 会静默截断** ——
> 我们的正则保证都是 3 个，所以安全。**但在别处用 `zip` 一定要想清楚长度是否可靠。**

## 11. 常见错误

| 现象 | 原因 | 解法 |
|------|------|------|
| `int("１")` 抛 `ValueError` | 全角数字 | 先 `unicodedata.normalize("NFKC", s)` |
| 正则匹配了 `123456789` 这种 | 用了 `\d{3}` + 没加 `^…$` | 用 `re.fullmatch` 或显式 `^$` |
| `re.match` 在中间匹配成功 | `match` 只要求从开头，不要求到结尾 | 用 `fullmatch` |
| `None` 进来炸 `AttributeError` | 没做空值检查 | `if not raw: raise ...` |
| dataclass 字段名打错没报错 | 用了 dict 或 `getattr` | 用 `@dataclass` + 直接属性访问 |
| 全角"＋"没处理 | 只 `replace("１","1")` | 用 NFKC，别手工列举 |

## 12. 自测题

1. 任务码的 4 组分别是什么含义？举一个例子逐组说明。
2. `NFKC` 里的 K 是什么意思？为什么不用手工 `replace`？
3. 为什么要用 `[1-6]` 而不是 `\d`？
4. "语义校验"和"形状校验"的区别是什么？各举一个例子。
5. 语义校验挡不住的"读串码"问题，怎么解决？
6. 12mm 的字在 150 DPI 下是多少像素？为什么这个换算和屏幕选型有关？

<details>
<summary>参考答案</summary>

1. 第1组=第一批颜色与搬运顺序、第2组=第一批放置位置、第3组=第二批颜色与顺序、第4组=第二批放置位置。`156+123+516+231`：第一批红→黑→浅蓝，放 1、2、3 号；第二批黑→红→浅蓝，放 2、3、1 号。
2. K = Kompatibility（兼容）。NFKC 用标准库的完整映射表把全角/兼容字符统一成标准形式；手工 `replace` 永远会漏掉新的兼容字符。
3. 因为颜色编号只有 1~6，`\d` 会放行 0、7、8、9，迫使你在两层重复校验；能在一层拦住就不留到下一层。
4. 形状校验只查"4 组 × 3 位 × 1~6"（如 `12+123+516+231` 长度错）；语义校验查"内部逻辑"（如 `155` 颜色重复）。
5. 加确认机制：多帧读到同一内容、显示在屏幕上人工确认、或结合"只能读一次+读的位置"等外部信息。语义校验本身无法解决。
6. 12 × 150/25.4 ≈ 71 px。因为像素与毫米的换算依赖 DPI，选屏时必须用屏的实际像素密度反算是否装得下。

</details>

## 13. 小结

| 你学到的 | 一句话 |
|---------|--------|
| 任务码结构 | 4 组 × 3 位 × `+` 连接，颜色 1~6，位置 1~3 |
| 归一化 | `NFKC` + 去空白，一行解决全角/空格/换行 |
| 正则 | `^[1-6]{3}(\+[1-6]{3}){3}$`，`[1-6]` 比 `\d` 更早拦住错 |
| 分阶段校验 | 分组 → 长度 → 字符 → 语义，每层报错精确到"第几组" |
| 语义约束 | 颜色不重复、位置不重复 —— **赛题没明说，是推出来的** |
| 三道防线 | 形状 / 语义 / **确认机制**，最后一道对应"任务码显示装置" |
| 12mm 换算 | 需要像素 = 12 × DPI / 25.4；150DPI→71px，本示例 64px 只有 10.8mm（不合格） |
| 数据建模 | `dataclass` + `tuple` = 打错就报错 + 不可变，比 dict 安全 |
| 模型不足 | 位置编号"分区"问题被练习 8-B 暴露 —— **发现模型不够比写能跑的代码更重要** |
