## 1. 本课要解决的问题

第 03 课你读过这么一行：

```
Decoded(data=b'156+123+516+231', type='QRCODE', rect=Rect(left=40, top=40, width=210, height=210), polygon=[Point(x=40, y=40), ...], quality=1, orientation='UP')
```

新手一般只取 `data`，剩下全扔掉。**这等于买了一台带测距仪的相机，只用来拍照。**

但机器人真正的问题是：

| 问题 | 需要哪个字段 |
|------|-------------|
| 码在画面左边还是右边？（要不要转） | `rect` / `polygon` |

| 码够大吗？（要不要往前挪） | `polygon` 边长 |
| 这张图里的码可信吗？ | 需要小心，`quality` **不可靠** |

这一课把这些一个个验证清楚。**每个结论都有实测数据支撑，没有一句是"据说"。**

### 六个字段的用途一览

| 字段 | 类型 | 含义 | 机器人拿它干什么 |
|------|------|------|-----------------|
| `.data` | bytes | 码里装的原始字节 | **这是你最终要的东西** |
| `.type` | str | 码的种类（QRCODE/CODE128/EAN13…） | 判断"这是不是我要的那种码" |
| `.rect` | Rect | **轴对齐**包围盒（left/top/width/height） | 快速估算位置和大小 |
| `.polygon` | list[Point] | 码的**真实四角**（斜着时不是矩形） | 算倾角、算每格像素、算真实中心 |
| `.quality` | int | zbar 内部质量分 | ⚠️ **不要当清晰度用**，见第 6 节 |
| `.orientation` | str | 朝向枚举（UP/LEFT/RIGHT/DOWN） | ⚠️ **不是倾角**，见第 5 节 |

> **批注：`Rect` 和 `Point` 是 pyzbar 自己定义的小类，不是 numpy 的东西。**
> 它们只有属性没有方法（`rect.left`、`point.x`），取值要用 `.` 而不是 `[0]`。
> 这是新手最常踩的坑之一：写 `r.rect[0]` 会报 `TypeError`。

## 3. 关键区别：`rect` 是"包围盒"，`polygon` 是"真四角"

看第 3 步里旋转 30° 那个码：

```
文件：10_rot30.png   图片尺寸：398x398
    .rect        = Rect(left=55, top=55, width=287, height=287)
    .polygon     = [Point(x=55, y=160), Point(x=160, y=342), Point(x=342, y=237), Point(x=237, y=55)]
```

**同样是这个码**：

- `rect` 说它 287×287 —— 因为它必须是**正着**的矩形（轴对齐）
- 但 `polygon` 四条边长都是 **210.1px**

```
287 = 210 × (cos30° + sin30°) = 210 × 1.366 ≈ 287     ← 数学对得上
```

> **打个比方**：你把一张方形纸片转 30° 拍下来。
> `rect` 是"能盖住这张纸片的最小正放矩形"（会变大）；
> `polygon` 是"纸片自己的四个角"（永远不变）。
>
> **所以：算大小要用 `polygon`，用 `rect` 会随角度膨胀，最多差 √2 倍（45° 时）。**

### 陷阱：`polygon` 只框"数据区"，不含白边

这是我在写这一课时专门验证的一个细节。看 A4 码板那张图：

实测：`polygon` 边长 = **343.0px**。

已知：`12_board_a4.png` 里码是 **80mm = 472px**（150 DPI），version 1 = 21 有效格 + 8 格白边 = 29 格。


## 5. 倾角：`orientation` 会骗你

这是本课最容易搞错的地方，我用实测数据说清楚。

<details>
<summary>参考结果（第 3 步）</summary>

```
文件：10_rot30.png
    .orientation = UP
    → 码相对画面水平线的夹角 ≈ 30.0°

文件：10_rot45.png
    .orientation = LEFT          ← 变了！
    → 码相对画面水平线的夹角 ≈ 44.8°

文件：10_rot90.png
    .orientation = LEFT          ← 但夹角是 0°！
    → 码相对画面水平线的夹角 ≈ 0.0°
```

</details>

我另外测了 `10_rot180.png`：`orientation = DOWN`，夹角 0.0°。

### 三句话总结

1. **`orientation` 只有 4 个值**（UP/LEFT/RIGHT/DOWN），它表示"**zbar 把这四个定位图案
   分别当成了哪个角**"，不是"码歪了多少度"。
2. **转 90° 时 `orientation` 变成 LEFT，但夹角是 0°** ——
   因为码的边依然和画面水平线平行，视觉上"没歪"。
3. **想算倾角，只能用 `polygon` 的四个顶点坐标。**

### 正确的倾角算法

```python
import math  # 角度换算要靠 atan2 和 degrees

def qr_tilt_deg(d):  # 传一个 Decoded，返回倾角
    """码相对画面水平线的夹角，范围 0~45。0 = 摆正。"""
    angles = []  # 收集四条边的方向角
    for i in range(4):  # 四个顶点连出四条边
        a, b = d.polygon[i], d.polygon[(i + 1) % 4]  # 相邻两点成一条边
        # atan2 给的是弧度，要先转成角度
        angles.append(math.degrees(math.atan2(b.y - a.y, b.x - a.x)))
    # 每条边离水平线有多近；正方形码四条边结果一致
    return min(min(abs(x), abs(abs(x) - 180)) for x in angles)
```

实测输出：

| 图片 | `orientation` | `qr_tilt_deg()` |
|------|--------------|-----------------|
| `01_clean.png` | UP | 0.0° |
| `10_rot10.png` | UP | 9.9° |
| `10_rot30.png` | UP | 30.0° |
| `10_rot45.png` | LEFT | 44.8° |
| `10_rot90.png` | LEFT | 0.0° |
| `10_rot180.png` | DOWN | 0.0° |
| `11_perspective.png` | UP | 13.1° |
| `13_scene.png` | UP | 0.7° |

> **批注：为什么只用"最小夹角"，不区分正负？**
> 因为**对一个正方形码来说，"歪 +30°"和"歪 -30°"在信息上完全等价** ——
> 两种情况都需要你转 30° 摆正，只是转的方向不同。
> 如果你真的需要方向（比如机械臂往哪边转），得用**两条边的长短/朝向差异**判断，
> 那是第 12 课"进阶 D"的内容（OpenCV 的四角检测，它给的是有顺序的角点）。

> **⚠️ 注意 `11_perspective.png` 的 13.1° 是"透视歪斜"，不是"平面旋转"。**
> 那张图是斜着拍的：四条边长分别是 172.0 / 160.4 / 167.4 / 147.0 —— **不相等**！
> 正方形码在透视下会变成梯形，这时"倾角"这个概念本身就模糊了。
> 一个实用的判据写在下面（练习 5-E）。

## 6. `quality` 不能当"清晰度"

<details>
<summary>参考结果（第 4 步）</summary>

```
文件：14_barcode_code128.png   图片尺寸：350x280
    .type        = CODE128
    .quality     = 178
    .polygon     = [Point(x=34, y=11), ..., Point(x=313, y=12)]
    → 码的中心点 = (173, 99)

文件：15_barcode_ean13.png   图片尺寸：523x280
    .type        = EAN13
    .quality     = 355
    .polygon     = [Point(x=76, y=11), ..., Point(x=447, y=12)]   ← 5 个点！
```

</details>

**`quality` 的值：二维码恒为 1，CODE128 是 178，EAN13 是 355。**

| 观察 | 结论 |
|------|------|
| 所有二维码（包括 30°、45°、透视、合成场景里的）`quality` **都是 1** | 对 QR 它几乎无信息量 |
| 条形码的 `quality` 是几百 | 不同 `type` 的分数量纲不同，**不可比** |
| 我见过糊图也能读到、`quality` 仍是 1 | **拿它当"清晰度阈值"会误判** |

> **正确的"清晰度"判据是什么？**
> **每格像素**（第 7 节的方法）。这是物理量，可解释、可跨图比较、能指导距离。
> `quality` 是 zbar 内部的一个副产品，**它不是为"测量"设计的**。
>
> **这是一条重要的工程态度**：不要随便拿一个"看起来像分数"的字段当判据，
> 先搞清楚它的量纲和含义。

### 顺带：一维码的 `polygon` 有 5 个点

`EAN13` 的 `polygon` 是 **5 个点**（`CODE128` 是 4 个）。所以：

> **🚫 片段（不能单独运行）** —— 它遍历的是上一段拿到的 Decoded 对象 d，单独复制会报 `NameError: name 'd' is not defined`。完整可运行版：`python code/lesson05_inspect_result.py`。

```python
# EAN13 的 polygon 是 5 个点，别写死 4
for i in range(len(d.polygon)):        # ✅ 用 len()：一维码可能是 5 点
    ...                                # 每个顶点都要处理，别漏
# 不要写死 range(4)                              ← 在一维码上会漏掉一条边
```

这也解释了脚本里为什么写 `if r.polygon and len(r.polygon) >= 4:` ——
**防御式写法**：`polygon` 可能是空的（某些失败情况），也可能不是 4 个点。

## 7. 动手 3：由 `polygon` 反推"每格多少像素"

<details>
<summary>参考结果（第 6 步）</summary>

```
用法：每格像素与距离成反比 —— 每格像素翻倍，就等于靠近一半的距离。
```

### 计算过程（一步都别跳）

> **🚫 片段（不能单独运行）** —— `polygon` 和 `math` 都来自上文（`polygon` 是上一段的 `d.polygon`），单独复制会报 `NameError`。完整可运行版：`python code/lesson05_inspect_result.py`。

```python
side = math.hypot(polygon[1].x - polygon[0].x, polygon[1].y - polygon[0].y)  # 第一条边 = 80.0px
px_per_module = side / 21          # 3.81 ← 除 21 有效格，不是 29
```

**为什么除 21 而不是 29？** 第 3 节已经验证过：`polygon` 不含白边。

### 这个数字怎么用？

**每格像素**是你能算出的、最接近"成像质量"的物理量。它直接告诉你两件事：

1. **该不该往前开**：3.81px/格 已经不错，但真实摄像头画面比合成图脏得多，
   留一倍余量更稳（第 09 课会告诉你真实阈值）
2. **和距离成反比**：距离减半 → 每格像素翻倍。
   所以如果你想从 3.81 提到 7.6，**靠近一半距离**就够了（第 12 课进阶 A 会给出精确公式）

> **批注：`03_size_40.png` 为什么还能读？**
> 那张图整图 40px，数据区 = 40 × 21/29 = 28.97px，每格 = 28.97/21 = **1.38px**。
> 和上面"清洁合成图 1.4px 就能读"完全吻合 —— **两处独立算法的结论对上了**。
> 这种"用两种方法交叉验证同一个数字"的习惯，能帮你在赛场上快速定位问题：
> 是"码太小"还是"画面太脏"。

## 8. 多码场景：怎么挑出"我要的那个码"

<details>
<summary>参考结果（第 5 步）</summary>

```
  ── 第 1 个码 ──  666+111+222+333   rect 左上角 (624, 44)   中心 (687, 107)
  ── 第 2 个码 ──  231+312+456+123   rect 左上角 (334, 44)   中心 (397, 107)
  ── 第 3 个码 ──  156+123+516+231   rect 左上角 (44, 44)    中心 (107, 107)
```

</details>

**两种常用组织方式**：

> **🚫 片段（不能单独运行）** —— results 是上一段 decode 的返回值，单独复制会报 `NameError: name 'results' is not defined`。完整可运行版：`python code/lesson05_inspect_result.py`。

```python
# 方式一：按内容建索引（适合"我知道我要什么内容"）
table = {d.data.decode(): d for d in results}  # 内容当键，码对象当值
task = table.get("156+123+516+231")  # 用内容直接取，取不到给 None

# 方式二：就近选取（适合"我只信画面中间那个码"）
def nearest_to(results, cx, cy):  # cx/cy 是参考点：画面中心
    def dist2(d):  # 平方距离，省一次开方
        ex = d.rect.left + d.rect.width / 2  # 由 rect 反推中心 x
        ey = d.rect.top + d.rect.height / 2  # 由 rect 反推中心 y
        return (ex - cx) ** 2 + (ey - cy) ** 2  # 越小说明离参考点越近
    return min(results, key=dist2)  # 取距离最小的那个码
```

> **为什么"就近选取"在赛场上很实用？**
> 因为你的摄像头可能一次扫到：**任务码板 + 旁边物料上的标签 + 对手赛场的码板**。
> 这时候"选画面中心最近的"比"选第一个读到的"稳得多 ——
> 你本来就该把摄像头对着自己的码板。

写一个 `inspect(path)` 函数，打印：内容、中心点、倾角、数据区边长、每格像素。

<details>
<summary>参考答案</summary>

```python
# ══════ 环境准备（每个示例都一样，照抄，不用改任何东西）══════
import os, sys
ROOT = "/home/kata/Desktop/logisticsCV/zbar二维码从零到赛场"   # 教程根目录
os.chdir(ROOT)                                    # 让示例里的 "assets/xxx" 找得到
sys.path.insert(0, os.path.join(ROOT, "code"))    # 让 import zbar_bootstrap 找得到
import zbar_bootstrap
zbar_bootstrap.ensure()                           # 确认 zbar 已就绪（第 02 课验证过）
from PIL import Image
from pyzbar.pyzbar import decode
# ══════════════════════════════════════════════════════════

import math  # 三角函数：量边长、算角度
from PIL import Image  # 打开图片文件
from pyzbar.pyzbar import decode  # zbar 入口：图片进，结果出

def inspect(path):  # 传一张图，打印它的体检报告
    for d in decode(Image.open(path)):  # 一张图可能有多个码
        # ═══ 1. 由 rect 反推中心点 ═══
        cx = d.rect.left + d.rect.width // 2  # 左上角 x 加半个宽
        cy = d.rect.top + d.rect.height // 2  # 左上角 y 加半个高
        # ═══ 2. 量四条边、算倾角 ═══
        sides = []  # 四条（或五条）边长
        angles = []  # 每条边的方向角
        n = len(d.polygon)  # 二维码 4 点，一维码 5 点
        for i in range(n):  # 顶点两两相连成边
            a, b = d.polygon[i], d.polygon[(i + 1) % n]  # 相邻两点
            sides.append(math.hypot(b.x - a.x, b.y - a.y))  # 勾股算像素长
            # atan2 出弧度，转成角度存起来
            angles.append(math.degrees(math.atan2(b.y - a.y, b.x - a.x)))
        tilt = min(min(abs(x), abs(abs(x) - 180)) for x in angles)  # 0~45
        side = max(sides)  # 最长边当数据区边长
        ratio = max(sides) / min(sides)  # 大于 1.1 说明有透视
        # ═══ 3. 汇总成一行体检表 ═══
        print(f"{d.data.decode():<18} 中心({cx},{cy})  夹角 {tilt:5.1f}°  "
              f"数据区边长 {side:6.1f}px  每格 {side / 21:5.2f}px  最长/最短 {ratio:.3f}")

inspect("assets/13_scene.png")  # 拿合成场景图试一下
```

参考结果：

```
156+123+516+231    中心(318,236)  夹角   0.7°  数据区边长   81.0px  每格  3.86px  最长/最短 1.025
```

> **两个小细节值得注意：**
> 1. 这里"数据区边长"取的是**最长边**（81.0px），而第 7 步的脚本取的是**第一条边**（80.0px），
>    所以一个是 3.86px/格、一个是 3.81px/格。**合成图有轻微透视/抗锯齿，两条边差 1 像素**，
>    两种算法结论一致：**约 3.8px/格**。
> 2. `最长/最短 = 1.025` —— 几乎完美正方形，说明这张合成场景是**正面拍的**。
>    拿这个数和练习 5-E 的判据（>1.1）对照，你就有了一个"透视程度"的量化指标。

</details>

```python
    def dist2(d):  # 平方距离，省一次开方
        ex = d.rect.left + d.rect.width / 2  # 码中心 x
        ey = d.rect.top + d.rect.height / 2  # 码中心 y
        return (ex - cx) ** 2 + (ey - cy) ** 2  # 越小离参考点越近
    return min(results, key=dist2)  # 取最小的那个码

# 参考点挪到左边，选中的码就换了
```

### 练习 5-C：`orientation` 填空题

不运行，先预测 `10_rot180.png` 的 `orientation` 和夹角，再验证。
再预测"转 200°"会得到什么。

<details>
<summary>参考答案</summary>

预测：`orientation = DOWN`，夹角 **0.0°**。

实测：

```
文件：10_rot180.png
    .orientation = DOWN
    → 码相对画面水平线的夹角 ≈ 0.0°
```

**为什么夹角是 0？** 转 180° 后，码的边依然与画面水平线平行，只是**上下颠倒了**。
`orientation = DOWN` 正是在告诉你"定位图案在下面"。

> **转 200° 呢？** 等价于转 20°（200 - 180 = 20，多转的那部分是上下颠倒）。
> 实测思路：夹角 ≈ 20°，`orientation` 会是 UP 或 DOWN 之一。
> **重点不是背答案，而是理解"倾角"和"朝向"是两个独立的量。**

</details>

### 练习 5-D：为什么 `rect` 在 45° 时会变 √2 倍？

用 `10_rot45.png` 的数据验证：`rect` 边长 298，`polygon` 边长 210.0。
298 / 210 ≈ ? 和 √2 比一比。（提示：45° 时包围盒 = 码宽 × (cos45+sin45)）

<details>
<summary>参考答案</summary>

```
rect 边长 = 298，polygon 边长 = 210.0（这是 ×10 box_size 的 21 格）
298 / 210 = 1.419
√2        = 1.414
```

**几乎相等。** 误差 0.4% 来自取整（`rect` 是整数像素）。

> **推导**：边长 L 的正方形转 45° 后，包围盒 = L·cos45° + L·sin45° = L·√2。
> 这就是"45° 时 `rect` 膨胀最多"的原因。

</details>

### 练习 5-E：判断"是不是斜着拍的"

写一个判据：用 `polygon` 四条边的长度，如果**最长边 / 最短边 > 1.1**，
就判定"有明显透视"，该重拍或该用第 12 课的摆正方案。

<details>
<summary>参考答案</summary>

```python
def perspective_ratio(d):  # 最长边 ÷ 最短边
    sides = []  # 先收集全部边长
    n = len(d.polygon)  # 二维码 4 点，一维码 5 点
    for i in range(n):  # 相邻两点连成一条边
        a, b = d.polygon[i], d.polygon[(i + 1) % n]
        sides.append(math.hypot(b.x - a.x, b.y - a.y))  # 勾股算像素长
    return max(sides) / min(sides)  # 1.000 就是正方形

def need_retake(d, limit=1.1):  # 1.1 是实测出来的经验线
    return perspective_ratio(d) > limit  # True 就该重拍或摆正
```

实测各图的 `最长/最短`：

| 图片 | 最长/最短 | 结论 |
|------|----------|------|
| `01_clean.png` | 1.000 | 正面拍 |
| `13_scene.png` | 1.025 | 几乎正面 |
| `11_perspective.png` | **1.170**（172.0 / 147.0） | 明显透视，建议摆正/重拍 |
| `12_board_a4.png` | 1.000 | 正面 |

> **`11_perspective.png` 的 1.170 > 1.1 → 触发"该摆正"。**
> 这正是第 12 课进阶 D 要解决的问题：用 OpenCV 找到四个角，把梯形"拉"回正方形，
> 再交给 zbar。

</details>

## 10. 常见错误

| 报错 / 现象 | 原因 | 解法 |
|------------|------|------|
| `TypeError: 'Rect' object is not subscriptable` | 写了 `r.rect[0]` | 用 `r.rect.left` |
| `TypeError: 'Point' object is not subscriptable` | 写了 `p[0]` | 用 `p.x` / `p.y` |
| `IndexError` 遍历 `polygon` | 一维码有 5 个点，或写死 `range(4)` | 用 `range(len(d.polygon))` |
| 倾角算出来是 90°/180° 这种怪值 | 直接用了 `polygon` 的某条边角度，没做归一化 | 用第 5 节的 `min(abs(x), abs(abs(x)-180))` |
| 每格像素普遍偏小 | 除错了（除了 29 而不是 21） | `polygon` 不含白边，除**有效格数** |
| 靠 `orientation` 判断摆动方向 | `orientation` 只有 4 个枚举值 | 用 `polygon` 算角度；要方向得用 OpenCV 角点 |

## 11. 自测题

1. `rect` 和 `polygon` 的根本区别是什么？45° 时两者相差多少？

   <details>
   <summary>参考答案</summary>

   `rect` 是轴对齐包围盒（会随旋转膨胀），`polygon` 是真实四角。45° 时 `rect` ≈ `polygon` × √2（实测 298/210 = 1.419）。

   </details>

2. `polygon` 框的是"整张码"还是"数据区"？怎么验证的？

   <details>
   <summary>参考答案</summary>

   只框数据区。用 `12_board_a4.png` 验证：80mm=472px 含白边，`polygon` 边长 343 ≈ 472×21/29。

   </details>

3. 已知 `polygon` 边长 80px、任务是 version 1 的码，每格多少像素？

   <details>
   <summary>参考答案</summary>

   80 / 21 = **3.81 px/格**。

   </details>

4. 为什么不能用 `orientation` 判断倾角？转 90° 时它是什么？

   <details>
   <summary>参考答案</summary>

   它只有 UP/LEFT/RIGHT/DOWN 四个枚举值，表示"定位图案被认成哪个角"。转 90° 时是 LEFT，但夹角是 0°。

   </details>

5. `quality` 能当清晰度阈值吗？为什么？该用什么代替？

   <details>
   <summary>参考答案</summary>

   不能。QR 恒为 1，条形码是几百，量纲不可比，与清晰度无单调关系。应改用 `polygon` 边长 ÷ 有效格数 得到的"每格像素"。

   </details>

6. 一张图里有 3 个码，`results[0]` 是最左边那个吗？为什么？

   <details>
   <summary>参考答案</summary>

   不一定。顺序是 zbar 内部扫描顺序（实测右边那个反而排第一）。要稳定就自己按 `rect.left` 排序，或用"就近选取"。

   </details>

## 12. 小结

| 你要的 | 该用 | 不该用 |
|-------|------|-------|
| 内容 | `.data.decode()` | —— |
| 位置 | `.rect` 中心 / `.polygon` 中心 | 只看 `results[0]` |
| 大小 | `polygon` 边长 ÷ **21** | `.rect.width`（会随角度膨胀） |
| 倾角 | `.polygon` 顶点算 atan2 | `.orientation`（只有 4 值） |
| 清晰度 | 每格像素 | `.quality`（量纲混乱） |
| 透视程度 | 最长边/最短边 > 1.1 | —— |
| 该不该往前开 | 每格像素 < 3 就靠近 | —— |

**一句话**：`rect` 给你"大概在哪"，`polygon` 给你"到底什么样"，
`orientation` 和 `quality` 这两个"看起来很专业"的字段，**恰恰是最容易误用的两个**。
