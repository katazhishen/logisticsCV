# 比赛读码（智能搬运赛项 · 二维码信息读取）

这个小项目只干一件事：**让小车在赛场上把墙上的 80×80mm 二维码读出来，翻译成能直接用的搬运任务单**。
按命题要求把「读取二维码」这一步做完整：**找码 → 预处理 → 解码 → 对齐（透视校正）→ 解析任务码 → 输出数据 + 存盘**，
并且带一个实时窗口，能看见摄像头画面、画框、定帧那一刻的图和透视对齐后的码。

环境用你本机的 conda 环境 `OpenCV_Linux`（Python 3.11.16 + cv2 5.0.0）：

```bash
PY=/home/kata/yes/envs/OpenCV_Linux/bin/python
```

## 2. 窗口怎么看

```
┌──────────────────────────────┬───────────────────────────────┐
│ FPS / decode 耗时 / 预算       │  FROZEN   ALIGNED   BINARY    │  ← 三联：定帧原图裁剪、
│ level 原图   streak 2/2       │  ┌────┐  ┌────┐  ┌────┐       │     透视对齐正视图、
│ LIVE 自动定帧 / FROZEN        │  │ 码 │  │ 码 │  │二值│       │     二值图
├──────────────────────────────┤  └────┘  └────┘  └────┘       │
│                              ├───────────────────────────────┤
│   摄像头实时画面              │  任务码  156+123+516+231       │  ← 识别出的数据（中文面板）
│   绿框 = 包围盒               │  第一批：颜色顺序 红-黑-浅蓝    │
│   青框 = 数据区四个真角        │  第二批：颜色顺序 黑-红-浅蓝    │
│   白十字 = 码中心             │  解码器 / 预处理级别 / 耗时     │
│                              │  码边长 / 每格像素 / 估算距离   │
└──────────────────────────────┴───────────────────────────────┘
```

| 按键 | 作用 |
|------|------|
| `q` / `Esc` | 退出 |
| `空格` | 手动定帧 / 解除定帧（读到码会自动定帧 5 秒） |
| `s` | 把当前帧 + 对齐图 + 数据存到 `out/` |
| `r` | 清空"连续确认"状态，重新开始 |

**为什么要有"定帧"**：赛场上你只需要读一次。定帧 = 把"读到的那一刻"冻住，方便核对，也让主控程序拿到确定的图。

## 3. 识别流水线（为什么这样排）

`reader.py` 里每一级都是一次"换一种看法"再交给 zbar。顺序按**实测耗时从便宜到贵**排，找到即停：

| 级别 | 处理 | 治什么病 | 实测耗时 |
|------|------|---------|---------|
| L0 | 原图灰度 | 正常画面（多数情况一次就中） | ~2ms |
| L1 | 中值滤波 3×3 | 椒盐噪声（脏镜头、传感器噪点） | ~2ms |
| L2 | OTSU 二值 | 光照不均、对比度低 | ~2.5ms |
| L3 | CLAHE 均衡 | 局部过暗 / 过亮 | ~2ms |
| L4 | 反色 | 浅色码印在深色底上 | ~2ms |
| L5 | 中心裁剪 + 2× | 码只占画面中间一小块 | ~1.5ms |
| L6 | 放大 2×（最近邻） | 码太小（每格 2~3px） | ~9ms |
| L7 | 放大 4×（最近邻） | 码极小 | ~26ms |
| L8 | 放大 4×（三次插值） | 硬边被糊过（缩放过的图） | ~26ms |
| L9 | OpenCV 检测器兜底 | 前九级全都没读出来时 | 十几 ms |

**时间预算**：`--budget 40`（默认）表示"这一帧最多花 40ms 解码，超了就放弃、先把画面刷出来"。
比赛时主循环不能被读码拖死——宁可这一帧不读，也不能让车停在原地。

**对齐（识别对齐）**：解码成功后拿到 zbar 的 `polygon`（数据区四个**真角**，不是轴对齐包围盒），
用 `cv2.getPerspectiveTransform` + `warpPerspective` 把它摊平成 240×240 的正视图，
再做一次 OTSU 得到二值图 —— 这就是窗口里 `ALIGNED` / `BINARY` 两格。斜着拍、转着拍的码都会被转正。

**任务码解析**：`156+123+516+231` → 四组三位数 → 颜色名（红1 黄2 蓝3 绿4 黑5 浅蓝6）+ 位置编号，
带 NFKC 全角归一化、正则校验、语义校验（同一组里颜色/位置不能重复），错就告诉你**错在哪一组**。

**距离估算**：`d = f × W / w`，其中 `f = 1475px`（第 12 课标定值）、`W = 80mm`、`w = 码边长像素`。
窗口右下角会直接告诉你"现在大约多远"，方便判断要不要再往前开一点。

## 4. 和比赛规则对上了哪些点

| 命题要求 | 本项目的对应 |
|---------|-------------|
| 二维码 80×80mm（含边框），A4 板上居中 | `gen_codes.py` 生成 A4@300DPI 码板，码正好 945px = 80.0mm，红线标出裁剪边界 |
| 任务码 = 四组三位数，`+` 连接 | `parse_taskcode()` 完整解析 + 四类校验 + 中文错误原因 |
| 颜色编号 红1 黄2 蓝3 绿4 黑5 浅蓝6 | `COLOR_NAME` 表，输出直接给"红-黑-浅蓝"这种顺序 |
| 完全自主，只能"一键启动"一次 | 读码是纯本地计算，无网络、无外部控制；`--confirm 2` 防单帧误读 |
| 时间紧（调试剩 1 分钟抽签、剩 30s 待机） | 单帧预算 40ms + 找到即停；本机实测平均 17.7ms/帧 |
| 场地 2400×2400，最远处码只有约 35px 宽 | 见下表：**必须开过去再读**，不要指望远距离读 |

距离与可读性（`f=1475px`、`W=80mm`，每格像素 = 码宽 ÷ 29）：

| 距码距离 | 画面里码宽 | 每格像素 | 能不能读 |
|---------|-----------|---------|---------|
| 2950mm | 40px | 1.38px | 基本读不出 |
| 1967mm | 60px | 2.07px | 看相位，不稳 |
| 1475mm | 80px | 2.76px | 能读（本项目实测三张全中） |
| 983mm | 120px | 4.14px | 稳 |
| 590mm | 200px | 6.90px | 很稳 |

> 结论：**把"读码工位"设在距码 600~1000mm 的地方**，停稳再读，比一路上边开边读靠谱得多。

## 5. 参数速查

```bash
--cam 0            # 摄像头编号（本机 0 和 3 都是 640×480，1/2 是 360×360）
--budget 40        # 单帧解码预算 ms（越大越容易读出来，但主循环越容易被拖慢）
--confirm 2        # 连续 N 帧读到同一内容才算数（防误读）
--freeze-sec 5     # 自动定帧保持几秒
--frames 60        # 处理 60 帧后自动退出（自测用）
--image xxx.png    # 读一张图而不是摄像头
--demo 0/1/2       # 合成画面演示（不用摄像头、不用打印码）
--no-window        # 不弹窗（无显示器时用，比如上车 ssh 调试）
```

## 6. 输出给车用的数据

每次确认读到任务码，都会写这三个东西（`out/` 下）：

- `out/latest.json` —— **给主控程序读**（结构固定，覆盖写）：

```json
{
  "text": "156+123+516+231",
  "level": "原图", "ms": 17.8,
  "side_px": 133.2, "per_module_px": 6.34, "distance_mm": 886.0,
  "task": {
    "raw": "156+123+516+231",
    "batch1": {"colors": ["红","黑","浅蓝"], "positions": [1,2,3]},
    "batch2": {"colors": ["黑","红","浅蓝"], "positions": [2,3,1]},
    "summary": "第一批：颜色顺序 红-黑-浅蓝，位置 1-2-3\n第二批：颜色顺序 黑-红-浅蓝，位置 2-3-1"
```

- `out/read_log.csv` —— 每行一条 JSON 记录（时间、内容、级别、耗时、边长、距离），复盘用。

## 8. 常见问题

**打不开摄像头**：换编号试 `--cam 1` / `--cam 3`（本机 0、3 是 640×480）；先确认设备在：`ls /dev/video*`。
实在不行用 `--demo 0` 或 `--image codes/taskcode_156123516231.png` 先把逻辑跑通。

**窗口一闪而过 / 没有窗口**：你现在是 X11（`DISPLAY=:0`），正常；如果在 ssh 里跑，必须加 `--no-window`。

**远处读不出**：先看窗口右下角的"估算距离"。大于 1500mm 时每格不到 3px，读不出是正常的 ——
**开近到 600~1000mm**，或者换更高分辨率的摄像头（每格像素直接翻倍）。

**读得慢、画面卡**：降 `--budget`（比如 25），或每 3 帧才全流程扫一次（在主循环里加个计数器），
其余帧只跑 L0 原图。这是赛场上最实用的一招：**平时只跑最便宜的级别，偶尔才全流程**。

**打印出来的码扫不出**：打印必须 **100% 缩放**（别用"适合页面"），用亚光纸；打完后用尺量红线到红线，
应该是 90mm（80mm 码 + 两边各 5mm）。
